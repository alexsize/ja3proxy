# Диагностика

## Клиент не доверяет сертификату

Признаки: `unknown authority`, `certificate verify failed`, разрыв сразу после
ClientHello.

Проверьте, что клиент доверяет `credentials/cert.pem`, а сертификат и ключ
образуют пару. Для одноразовой проверки `curl` допустим параметр `-k`, но он не
подходит для проверки корректности цепочки доверия.

Если существует только один из файлов CA, JA3Proxy намеренно не запускается.
Восстановите правильную пару или переместите оставшийся файл и создайте новый CA.

## Порт уже занят

Измените порт прокси или панели:

```bash
./ja3proxy --listen 127.0.0.1:18080 --web-panel 127.0.0.1:19090
```

Не используйте один адрес и порт одновременно для прокси и веб-панели.

## Веб-панель регистратора не запускается

При `--capture-tls` панель должна быть привязана к loopback:

```text
127.0.0.1:9090
[::1]:9090
```

Адрес `:9090` означает прослушивание всех интерфейсов и отклоняется из
соображений безопасности.

## Нет наблюдений

Убедитесь, что:

1. задан `--capture-tls`;
2. клиент использует HTTP CONNECT или SOCKS5 через нужный порт;
3. после установления туннеля действительно начинается TLS;
4. фильтр поиска в панели очищен;
5. запрос не относится к обычному незашифрованному HTTP.

Проверьте `/api/v1/status`: поля `accepted`, `processed`, `dropped` и
`write_errors` помогают отличить отсутствие трафика от переполнения очереди или
ошибки экспорта.

## Регистратор показывает `recording_degraded`

Возможные причины:

- очередь переполнялась, и часть наблюдений потеряна;
- исчерпана квота JSONL;
- произошла ошибка записи или закрытия файла.

Прокси продолжает передавать трафик. Снизьте нагрузку, отключите raw, выберите
другой диск или новый файл и перезапустите процесс. Не дописывайте вручную в
активный JSONL.

## JSONL уже существует

Recorder не перезаписывает доказательные данные. Выберите новое имя:

```bash
./ja3proxy --capture-tls --capture-jsonl recordings/run-002.jsonl
```

## TLS на нестандартном порту

При включённом recorder SOCKS5-туннели передаются обработчику TLS независимо от
номера порта. В режиме MITM первая порция данных ожидается до пяти секунд. Для
server-first или нетипичного протокола используйте `PASSTHROUGH` либо отключите
recorder на этом запуске.

## Не работает следующий прокси

Проверьте схему и доступность:

```text
socks5://127.0.0.1:1080
http://user:password@127.0.0.1:3128
```

HTTP-прокси следующего уровня должен разрешать CONNECT к требуемому порту.
Адрес без схемы считается SOCKS5.

## Профиль не обновляется из файла

JSON должен содержать поддерживаемые `client` и `version`. Ошибка обновления не
заменяет текущий рабочий профиль. Изменение действует только для новых
соединений; уже открытый туннель сохраняет прежний ClientHello.

## Диагностический журнал

```bash
./ja3proxy --log-level debug
```

`--dump-traffic` выводит содержимое передаваемых данных и автоматически
подразумевает подробное журналирование. Этот режим чувствителен: используйте его
только на тестовых данных и не прикладывайте журнал к публичным задачам без
проверки содержимого.

## Минимальный отчёт об ошибке

Укажите:

- операционную систему и архитектуру;
- версию Go и ревизию JA3Proxy;
- команду запуска без паролей и секретов;
- протокол клиента и следующий прокси;
- ожидаемое и фактическое поведение;
- минимальный журнал с удалёнными чувствительными данными;
- воспроизводится ли проблема без `--capture-raw` и `--dump-traffic`.
